# 离线降级设计

> 上一级：[PLAN.md](../../PLAN.md)。补哲学审计 §3 批评 5（单人带宽天花板：无人值守降级仍缝，§5 结论）。只设计，不实现。遵守 D22：只给事实与验收。

## 降级链

模型不可用时按 主 → 备 → 本地 → 明确失败 逐级切换。每级粒度 = 请求级：先走 D13 原生自动重试（上限 + 退避，可关），重试耗尽才切下一级。本设计只管可用性降级，与 D19 强弱模型路由正交。

| 级 | provider | 系统事实 |
|---|---|---|
| 1 主 | deepseek-official | 全局默认模型；R10 实测可用（conversation-notes R10） |
| 2 备 | opencode-go | 备用 provider |
| 3 本地 | llama-server | 本地 8080；R10 教训：llama 超时曾致子代理卡死，故列最后 |
| 4 失败 | 明确失败语义 | 见下 |

明确失败语义（第 4 级）：三级全失败 → 不静默、不猜、不无限重试；子代理 report 原样回报父层（D7），父层 D13 checkpoint 保留现场，等人工接管。对齐 D30 边界：错误原样回报（证据），不静默降级。

D30 约束：降级目标 provider 必须 ∈ 授权集（默认 ∪ allowlist）；未授权目标在闸点硬拦 = 直接进第 4 级，不做尝试。授权后仍 403 属运行时额度问题，原样回报。

## 触发条件

切级触发 = D13 请求级重试耗尽后的失败判定：

1. 硬失败：401 / 403 / 404 / 连接超时（R10：llama 超时案例）。
2. 连续失败：同 provider 连续失败达阈值 → 切下一级。阈值 = 2 次（本设计提案，实施前按 D16 冻结）。
3. 无人值守场景：审查层用户不在场——后台任务（D20）+ 定时 checkpoint（D13）期间自动执行；这是 D11「放行」的形式化（用户不在场自动放行，而非逐次确认）。

不触发：单次失败未达阈值；错误类型可重试（llm/retry 原生兜底）；用户在场（非无人值守，降级链不自动跑）。

每次切级落盘降级事件：时间 / 当前 provider / 错误原文（D13 checkpoint 现场）。

## 恢复语义

- 自动：主 provider 健康探测通过（下一请求前轻量 ping）→ 切回主。
- 人工：审查层显式恢复（D13 rewind 或 checkpoint 现场重开）。
- 边界：恢复不回放降级期动作；降级期落盘结果保留；降级期失败现场不覆盖、不静默丢弃。

## 验收门（预注册，D16）

| 门 | PASS | KILL | NULL |
|---|---|---|---|
| 切级 | 主失败 → 备接管，同输入任务单次完成，降级事件落盘 1 条 | 降级静默（无落盘、无 report） | 用户在场：0 次降级动作 |
| 三级链 | 主+备失败 → llama-server 接管并完成或明确失败，切级决策 ≤ 3 轮 | 切级循环 > 3 轮（无上限无退避） | — |
| 全失败 | 1 次明确失败回报，含三级各错误原文，现场 100% 落盘 | 静默丢弃现场 | — |
