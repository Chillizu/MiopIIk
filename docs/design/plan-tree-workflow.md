# 计划树工作流（plan-tree 约定）

> 上一级：[PLAN.md](../PLAN.md)。对应决策 D21。来源：本会话用户提出（R7："写一个完整的计划…第一层是计划，第二层是文档和参考，还有对话记录简述"）+ 用户契约先行/单一事实来源习惯（Miooasis contracts、PEDA WATCHDOG）。

## 1. 定义

任何需要长期推进的项目或大计划，在动手实施前先在文件库建立一棵**计划树**：用目录与文件的引用关系承载全部规划状态，使任何新会话（含执行层 subagent）只读根文件即可无损理解项目。

## 2. 结构约定

| 层 | 内容 | 本树实例 |
|---|---|---|
| 第一层 | PLAN.md：总计划根（定位/目标/已确认决策清单/树索引/待确认项/下一步/维护规则） | [PLAN.md](../PLAN.md) |
| 第二层 | 文档和参考（调研/对照/来源）+ 对话记录简述（会话轮次要点 + 历史会话分析摘要 + 用户画像） | docs/research/、docs/profile/ |
| 第三层 | 设计细则（架构/协议/记忆/恢复/关键词）、预设骨架、可粘贴模板——挂在第二层之下 | docs/design/、presets/、templates/ |

层级语义是**引用关系**而非目录深度：上层只做索引与决策，下层承载细节与证据；每文件头部标注"上一级"链接。

## 3. 创建时机与规则

- 时机：需求定稿后、动手实施前；每个新项目或每个大特性一棵树。
- 单源事实：任何设计变更先改 PLAN.md 对应决策行，再改详情文档。
- 新会话入口：先读 PLAN.md 再干活（"计划即执行规格、零设计决策"）。
- 发现新偏好/教训 → 更新 profile 文档；重要结论升级为 PLAN.md 决策。
- 文件名英文（工具友好）、内容中文；无 Emoji、证据优先（用户风格）。
- 简洁原则（D22）：提示词与代码保持简洁——文档只给事实与验收，不给方法说教。
- 交叉链接：每个文件可被 PLAN.md 索引定位；模板文件必须可直接粘贴进 subagent prompt。

## 4. 与层级工作流的关系

- 本树 = 项目级记忆的核心 artifact（对应 OMP `local://PLAN.md` 语义与 `.dsh/plan/` 落位），也是契约先行纪律的载体（契约本身放项目 `.dsh/contracts/`）。
- 规划层在项目内写的 plan 文件 = 本树约定在项目工作区的实例化（第二层文档在项目侧的投影）；执行层只读引用切片相关文件，不做设计决策。
- 对话记录简述层替代"靠对话上下文续命"：每轮关键结论落盘，压缩/换会话不丢状态（对应 PEDA 的 WATCHDOG 动机）。

## 5. 验收模板（本树自用门，可复用于任何计划树）

- A1：约定文件全部存在且非空；
- A2：根文件含决策清单与待确认项且交叉链接有效；
- A3：文档完整覆盖此前产出，无凭空结论；
- A4：画像/摘要均有证据引用；
- A5：模板文件零设计决策可直接使用；
- A6：任何内容与已确认决策矛盾即 KILL，修正后重验。
